# BLE-протокол

Основной пользовательский сценарий описан в [Program API](11_program_api.md): готовые
программы выбираются, настраиваются и запускаются на самом слайдере. Характеристики ниже
составляют Advanced/compatibility API для ручного управления и диагностики.

Имя устройства: **Camera_Slider**

## Сервис

UUID: `4fafc201-1fb5-459e-8fcc-c5c9c331914b`

## Характеристики

### Program (READ / WRITE / NOTIFY)

UUID: `c0f1c001-0000-4000-8000-00000000c0de`

Версионированное управление готовыми программами. Программа по умолчанию — Ping-Pong.
Форматы request/status, готовые пакеты и требования к пульту приведены в
[docs/11_program_api.md](11_program_api.md).

### Command (WRITE)
UUID: `beb5483e-36e1-4688-b7f5-ea07361b26a8`

1 байт — код команды:

| Байт | Команда  | Действие                                      |
|------|----------|-----------------------------------------------|
| 'F'  | Forward  | Непрерывное движение вперёд / смена направления |
| 'B'  | Backward | Непрерывное движение назад / смена направления  |
| 'S'  | Stop     | Остановка любого движения                     |
| 'H'  | Home     | Запуск калибровки (хоминг)                    |
| 'G'  | Go home  | Переход к сохранённой домашней позиции        |
| 'Z'  | Set home | Сохранить текущую позицию как домашнюю        |
| 'R'  | Reset    | Сброс состояния ошибки                        |

`F` и `B` задают направление ручного движения и идемпотентны: повтор той же команды
ничего не меняет, противоположная команда меняет направление. Команда блокируется, если
соответствующий концевик уже нажат. Во время хоминга, движения к позиции, парковки и
Ping-Pong обе команды игнорируются.

### Speed (WRITE)
UUID: `d8de624e-140f-4a22-8594-e2216b84a5f2`

2 байта, uint16, little-endian — задержка между шагами в микросекундах.

```
[low_byte, high_byte]
```

Диапазон: 100–5000. Меньше = быстрее.

### Position (WRITE)
UUID: `a1b2c3d4-e5f6-4789-a012-3456789abcde`

4 байта, int32, little-endian — целевая позиция в шагах.

```
[byte0, byte1, byte2, byte3]
```

Ограничивается в [0, travelDistance]. Требуется калибровка. Без неё — команда игнорируется.

### Current (WRITE)
UUID: `f1e2d3c4-b5a6-4978-9012-3456789abcde`

2 байта, uint16, little-endian — ток мотора в мА.

```
[low_byte, high_byte]
```

Диапазон: 200–1500. Применяется мгновенно.

### Status (READ / NOTIFY)
UUID: `1c95d5e3-d8f7-413a-bf3d-7a2e5d7be87e`

11 байт, отправляется notify каждые 100мс при активном соединении. Первые 9 байт
совместимы со старым форматом статуса.

```
Байты 0–3: currentPosition (int32, little-endian)
Байт  4:   флаги (битовая маска)
Байты 5–8: travelDistance (int32, little-endian)
Байт  9:   state (uint8)
Байт  10:  errorCode (uint8)
```

Битовая маска (байт 4):

| Бит | Маска | Значение                |
|-----|-------|-------------------------|
| 0   | 0x01  | ENDSTOP_1 сработал      |
| 1   | 0x02  | ENDSTOP_2 сработал      |
| 2   | 0x04  | Идёт хоминг             |
| 3   | 0x08  | Калибровка выполнена     |
| 4   | 0x10  | Движение к позиции       |
| 5   | 0x20  | Мотор движется           |
| 6   | 0x40  | Идёт парковка            |

`state`: `0=IDLE`, `1=MANUAL`, `2=MOVE_TO_POS`, `3=HOMING`, `4=PARKING`,
`5=ERROR`, `6=SLEEP`, `7=PING_PONG`.

`errorCode`: `0=NONE`, `1=BLE_LOST`, `2=HOMING_FAIL`,
`3=ENDSTOP_FAULT` (зарезервирован).
