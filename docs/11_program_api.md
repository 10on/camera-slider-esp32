# Program API и рекомендации для пульта

## Зачем нужен отдельный Program API

Обычный сценарий управления должен оперировать готовой программой слайдера, а не
направлением мотора. Слайдер сам отвечает за траекторию, смену направления, концевики и
переходы state machine. Пульт:

1. выбирает программу;
2. показывает и меняет только её публичные параметры;
3. отправляет `START` / `STOP`;
4. отображает подтверждённое состояние из notify.

По умолчанию выбрана программа **Ping-Pong**. Низкоуровневые команды ручного движения,
абсолютной позиции и тока не удаляются, но относятся к отдельному Advanced API.

Такое разделение важно: `Forward` не означает «начать Ping-Pong». Это ручной jog, у
которого другой жизненный цикл и другие ожидания пользователя.

## BLE characteristic

Service UUID остаётся прежним:

`4fafc201-1fb5-459e-8fcc-c5c9c331914b`

Program characteristic (READ / WRITE / NOTIFY):

`c0f1c001-0000-4000-8000-00000000c0de`

### Request v1

Пульт пишет пакет из 6 байт:

| Offset | Поле | Значение |
|---:|---|---|
| 0 | `version` | `1` |
| 1 | `programId` | `0=Manual/Advanced`, `1=Ping-Pong` |
| 2 | `action` | `0=SELECT`, `1=START`, `2=STOP`, `3=CONFIGURE` |
| 3 | `speedPercent` | `1..100`, `0` — не менять |
| 4 | `startPoint` | `0=Center`, `1=Endstop 1`, `2=Endstop 2`, `0xFF` — не менять |
| 5 | `flags` | bit 0 — сохранить параметры в NVS; остальные зарезервированы |

Поля после обязательного заголовка в следующих версиях можно только добавлять в конец.
Неизвестную версию или некорректный диапазон слайдер игнорирует.

`SELECT` не запускает движение и не обязан менять параметры. `CONFIGURE` применяет
параметры к выбранной программе; скорость можно менять во время Ping-Pong. `START`
запускает выбранную программу только когда её prerequisites выполнены. `STOP` имеет
семантику безопасной остановки выбранной программы.

Флаг сохранения не следует ставить при каждом повороте энкодера: live-настройку лучше
держать в RAM, а записывать в NVS отдельным подтверждением пользователя.

### Status v1

Слайдер отправляет notify из 8 байт:

| Offset | Поле | Значение |
|---:|---|---|
| 0 | `version` | `1` |
| 1 | `selectedProgram` | текущий `programId` |
| 2 | `runState` | `0=stopped`, `1=running` |
| 3 | `speedPercent` | фактически применённая скорость `1..100` |
| 4 | `startPoint` | фактически применённая точка старта |
| 5 | `capabilities` | bit 0 — Ping-Pong поддержан; bit 1 — калибровка готова |
| 6 | `sliderState` | общий state слайдера |
| 7 | `errorCode` | общий код ошибки |

Notify является источником истины. Пульт не должен считать программу запущенной только
потому, что BLE write завершился успешно.

## Готовые пакеты Ping-Pong

Выбрать Ping-Pong, не меняя его сохранённые настройки:

```text
01 01 00 00 FF 00
```

Установить скорость 50%, не меняя точку старта и не писать NVS:

```text
01 01 03 32 FF 00
```

Установить скорость 50%, старт из центра и сохранить:

```text
01 01 03 32 00 01
```

Запустить / остановить:

```text
01 01 01 00 FF 00
01 01 02 00 FF 00
```

## Безопасность и состояния

- Ping-Pong требует выполненной калибровки (`capabilities & 0x02`).
- Концевики, реверс и ограничение движения принадлежат прошивке слайдера.
- Любой источник движения проходит низкоуровневую защиту: мотор не запускается в сторону
  уже нажатого концевика.
- Потеря BLE во время движения остаётся аварийным событием и останавливает мотор.
- Повторные `SELECT`, `CONFIGURE`, `START` и `STOP` должны восприниматься пультом как
  идемпотентные намерения; результат всегда уточняется по notify.
- При `sliderState=ERROR` пульт показывает ошибку и не предлагает `START`, пока ошибка не
  сброшена или не выполнено разрешённое восстановление.

## Advanced API

Существующие characteristics сохраняются для диагностики, ручной настройки и
совместимости:

- Command `F/B/S/H/G/Z/R` — ручное движение, homing и сервисные команды;
- Speed — legacy-интервал `100..5000` мкс/шаг;
- Position — абсолютная позиция;
- Current — ток драйвера;
- Status — подробная телеметрия мотора и state machine.

Advanced API нельзя использовать для имитации готовой программы. В частности, пульт не
должен самостоятельно реализовывать Ping-Pong последовательностью `F/B`: он потеряет
синхронизацию при задержках BLE, disconnect и срабатывании концевика.

## Рекомендуемый UX пульта

### Основной экран

- Название выбранной программы: `PING-PONG`.
- Подтверждённый статус `IDLE / RUNNING / ERROR` из Program notify.
- Основные параметры программы: скорость и стартовая точка.
- Одна явная кнопка `START / STOP`.
- Индикаторы E1/E2 и калибровки — только как телеметрия, без локальной имитации логики.

При первом подключении пульт отправляет только `SELECT Ping-Pong`, подписывается на notify
и заполняет UI фактическими настройками слайдера. Он не перезаписывает их своими
дефолтами.

### Настройка

- Энкодер скорости отправляет `CONFIGURE` с новым `speedPercent` и `flags=0`.
- Выбор `Center / Endstop 1 / Endstop 2` меняет `startPoint`.
- Отдельное действие `Save preset` повторяет последний `CONFIGURE` с `flags bit0=1`.
- Во время RUNNING разрешена live-настройка только тех параметров, которые явно
  поддержаны контрактом; сейчас это скорость.

### Advanced

Ручной jog, go-to-position, установка тока, home calibration и reset error должны быть на
отдельном экране `Advanced / Service`. Перед входом в него пульт отправляет Program
`STOP`. Выход из Advanced снова делает `SELECT Ping-Pong`, но не запускает его.

### Совместимость

Если Program characteristic отсутствует, подключён старый firmware:

- пульт помечает режим как `Legacy`;
- может оставить ручные `F/B/S` и legacy Speed;
- не показывает, что Ping-Pong управляется как preset;
- не подменяет Program API локальной автоматизацией.
